The problem

Forest Service cabins book out months ahead. Plans change and cancellations happen constantly, but an opening is gone within minutes, taken by whoever happened to be refreshing the page.

Who it's for

A local adventurer who already found the cabin they want and hit a wall. They'd go this weekend if something opened. Finding the cabin isn't the problem; the dead end after finding it is.

The key decision

Don't compete with Recreation.gov. It owns the data and the brand recognition. Ember is a layer on top: the cabin page shows just enough to confirm the place, then gets out of the way of availability and alerts.

One warm light source

The name comes from the product's core moment: a cabin opening up after months dark. An ember is what's left when the fire has almost gone out. It's still glowing, and still an opportunity if you move fast.

The product lives at night, on your phone in bed when the alert arrives, so the visual language does too. Every competitor defaults to daylight. On near-black forest green, the same orange family stops being a brand color and becomes a light source, reserved for the most important element on each screen.

Right-size the engineering to the data

Ember has two kinds of data with opposite shapes. That asymmetry, not a framework preference, decided the architecture: cheap data is loaded eagerly, and the expensive data only gets heavy machinery where it earns it.

Cabin facts
Availability
Shape
505 cabins from a one-time data dump. Small (about 30 KB gzipped) and frozen.
Live, per cabin and per month. Only Recreation.gov has it.
So
The whole set ships to the map once. Panning makes zero cabin requests. The page is cached and rebuilt daily.
Fetched on demand when you open a cabin. Showing it across the whole map would take about 500 live calls, so that's deferred.
Compare
Airbnb fetches per viewport because it has millions of listings. At 505, loading everything is simpler and feels faster.
Alerts are the one place that has to read live availability on a schedule. That's the pipeline below.
The alert check
1 · Trigger Scheduled cron

Vercel runs the check daily and authenticates with a shared secret, so nobody else can fire it.

2 · Check Find openings

Groups alerts by cabin, fetches each month once, then finds runs of at least N open nights in each alert's dates. Reads only.

3 · Send Claim, then email

Claims a row guarded by a unique constraint, then emails through Resend. An opening already sent is skipped.

4 · Report Count outcomes

Sent, duplicate and failed are tallied separately, so a broken write is never mistaken for a duplicate.

Ten watchers, one request

Fetches are batched per cabin, so popular cabins don't multiply load on Recreation.gov.

Safe to rerun

The database, not the code, guarantees each opening is emailed once. A retry or a manual run can't double-send.

Tested without a network

Check and send are separate modules that take their I/O as inputs, so both are unit-tested with fakes.

A known limit

Checks run once a day because Vercel's free tier caps crons at daily. Nothing in the pipeline assumes that; on a paid plan it would run every 15 minutes. A dev trigger forces a run for demos.

Three calls about structure

Browse · Map first A full-screen map, not a split list

Airbnb's 50/50 split works when there are 200 results in a few blocks and you need a list to compare. Cabins on public land are sparse. People orient by place first: which trails, is there a lake. So the map takes the whole screen and the cabin card floats on it, a move borrowed from AllTrails.

It's also the one light surface in a dark product. Light is for scanning a landscape; dark is for focusing on a decision.

Calendar · Cell states Availability was shown by dimming

Most nights at a popular cabin are booked, so most cells rendered dim and the calendar looked dead. Worse, booked nights you could tap were dimmer than past days you couldn't.

People wanted "any night this fall would do." Strict required the whole range to open, which never happens for a broad window. I tried a stepper, a segmented control and a sentence in Figma. The sentence won: it explains the model as you read it, and it scales from 1 night to 90.

The schema change shipped expand, migrate, contract, so the live app never ran against a database it didn't understand.
